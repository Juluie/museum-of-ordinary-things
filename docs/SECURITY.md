# Безопасность

## Модель доступа

| Кто | Что может |
|---|---|
| Посетитель (анонимно) | читать **только опубликованные** экспонаты через функцию `public-exhibits`; отправлять новую вещь через `submit-exhibit` |
| Хранитель (вход + запись в `admins`) | видеть все записи, одобрять, отклонять, снимать, удалять через `admin-exhibits` |
| Edge Functions | работают с секретным ключом Supabase, который есть только на сервере |

- У ролей `anon` и `authenticated` нет прав на таблицы; RLS включён и принудительный. Прямые запросы к `/rest/v1/exhibits` с publishable-ключом данных не вернут.
- Регистрация выключена. Любой вошедший пользователь без записи в `admins` получает 403 на каждой операции админки — проверка в каждом запросе, а не только при входе.
- Неопубликованный, отклонённый и несуществующий ID дают одинаковый ответ «не найден».
- Текст экспоната нельзя изменить после отправки (триггер в базе), номер выдаётся один раз при одобрении.

## Приватность фото

- Бакет `exhibit-images` приватный, публичных политик нет.
- В браузере фото уменьшается и перерисовывается через canvas (метаданные не переносятся). Это удобство, не защита.
- На сервере фото проверяется заново по содержимому файла (не по расширению), ограничиваются размер и число пикселей, затем пересохраняется в JPEG без EXIF/GPS/ICC. Исходный файл не сохраняется. Удаление GPS проверено тестом на реальном файле.
- Pending-фото лежат по неугадываемому пути. Когда экспонат снимают с публикации, файл переносится на новый путь — старые ссылки перестают работать.

## Срок временных ссылок

- Посетителям: `PUBLIC_SIGNED_URL_TTL_SECONDS` = 3600 (1 час). Если ссылка истекла, сайт сам запрашивает новую.
- Админке: `ADMIN_SIGNED_URL_TTL_SECONDS` = 600 (10 минут).
- Уже выданная ссылка действует до конца срока даже после снятия экспоната. Скопированные кем-то файлы удалить невозможно.

## Защита формы

Порядок проверок в `submit-exhibit`: приём открыт → скрытое поле-ловушка → формат ID отправки → Turnstile (действие `submit_exhibit`, проверка домена) → повтор той же отправки (идемпотентность) → лимит частоты → валидация текста → обработка фото → загрузка → запись.

- Лимиты: 3 в час и 10 в сутки с одного адреса, 100 в сутки всего. Считаются атомарно в базе.
- Адрес не хранится: в базу пишется HMAC(секрет, IP). Это не полная анонимизация — при знании секрета и IP хеш можно сопоставить.
- IP берётся только из `cf-connecting-ip`; если его нет, все такие запросы делят один общий лимит.
- Размер тела запроса ограничен до чтения.
- Любой текст выводится как текст: HTML не интерпретируется (проверено тестом).
- `public/_headers` задаёт CSP и запрет встраивания сайта во фреймы.

## Известные ограничения

Проверено автоматическими тестами локально, но **не** на настоящих сервисах:

1. Заголовок `cf-connecting-ip` в Supabase Edge Functions — нужно убедиться, что его нельзя подделать с клиента. Если окажется, что можно, лимиты по адресу ослабнут (общий суточный лимит останется).
2. Модуль обработки фото (ImageMagick wasm, ~15 МБ) — холодный старт может занимать несколько секунд; на бесплатном тарифе лимит CPU 2 с на запрос. Браузер заранее уменьшает фото, но очень сложные файлы могут не уложиться — пользователь увидит ошибку и сохранит текст.
3. Конкурентность лимитов проверена в PGlite (один процесс), а не под реальной параллельной нагрузкой.
4. Политики Storage не проверены на локальном Supabase (нет Docker). Проверка вручную — docs/SETUP_SUPABASE.md, раздел 9.
5. Turnstile снижает автоматический спам, но не модерирует содержимое. Всё проходит ручную проверку.
6. Демо-админка (`/admin` в demo-режиме) — незащищённый макет с вымышленными данными, это видно на странице.

## Работа с секретами

- Секреты не хранятся в репозитории, в `VITE_*` переменных и в логах. `.env`, `.env.*` (кроме `.env.example`) и `supabase/functions/.env` в `.gitignore`.
- Серверные секреты — только в Supabase (`supabase secrets set` или панель). Публичные значения — в Cloudflare Pages.
- `npm run check:bundle` проверяет сборку на секретные ключи Supabase, имена серверных секретов, приватные ключи и GitHub-токены. Запускается в CI.
- Логи функций не содержат текста историй, IP и токенов — только коды событий.
- Если секрет утёк: сразу создай новый в панели сервиса, обнови в Supabase, старый отзови. Для `RATE_LIMIT_HMAC_SECRET` — поменяй и `RATE_LIMIT_HMAC_KEY_VERSION`.
