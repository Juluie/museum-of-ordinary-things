# GitHub: как устроена работа с кодом

## Простыми словами

- **Папка проекта** — папка на компьютере (или в облачной среде), где лежат все файлы сайта. Здесь ты что-то меняешь.
- **Репозиторий** — эта же папка вместе со всей историей изменений. Копия хранится на GitHub, чтобы ничего не потерялось и можно было открыть с любого компьютера.
- **Commit (коммит)** — сохранённый снимок изменений с коротким описанием, например «Исправить кнопку». Как точка сохранения в игре: к ней всегда можно вернуться.
- **Push** — отправить новые коммиты из папки на GitHub. До push изменения есть только у тебя.
- **Branch (ветка)** — параллельная версия проекта. Главная ветка — `main`: то, что в ней, и есть сайт. В отдельной ветке можно экспериментировать, не трогая сайт.
- **Deploy (публикация)** — выкладка сайта в интернет. Здесь её делает Cloudflare Pages сам: увидел новый коммит в `main` → собрал → опубликовал.

## 1. Где находится проект

- Папка: `museum-of-ordinary-things/` (в облачной среде Perplexity Computer — `/home/user/workspace/museum-of-ordinary-things`).
- На GitHub: [github.com/Juluie/museum-of-ordinary-things](https://github.com/Juluie/museum-of-ordinary-things) — **приватный**, видишь только ты и те, кого пригласишь.

## 2. Репозиторий

Что в нём есть: код сайта (`src/`), миграции и функции Supabase (`supabase/`), тесты (`tests/`, `e2e/`, `src/test/`), документация (`docs/`).

Чего в нём **нет и быть не должно**: фото и истории посетителей, пароли, ключи, `.env`, дампы базы, `node_modules`, `dist`. Это прописано в `.gitignore`.

## 3. Как открыть проект заново

На новом компьютере (нужны Node 22 и Git):

```bash
gh repo clone Juluie/museum-of-ordinary-things   # или git clone https://github.com/Juluie/museum-of-ordinary-things.git
cd museum-of-ordinary-things
npm ci
npm run dev        # откроется demo-версия на http://localhost:5173
```

Через сайт: github.com → твой профиль → Repositories → museum-of-ordinary-things.

## 4. Как посмотреть изменения

```bash
git status            # какие файлы изменены и ещё не сохранены в коммит
git diff              # что именно поменялось
git log --oneline -20 # последние 20 коммитов
```

На GitHub: вкладка **Commits** — вся история; клик по коммиту показывает, какие строки изменились.

## 5. Как проверить проект

```bash
npm run check      # lint + типы + тесты + сборка + проверка на секреты
npm run test:e2e   # проверка в настоящем браузере (дольше)
```

После push то же самое запускает GitHub: вкладка **Actions**. Зелёная галочка у коммита — проверки прошли, красный крестик — что-то сломалось (клик покажет что).

## 6. Как сделать commit

```bash
git status                          # посмотреть, что изменилось
git add src/pages/HomePage.tsx      # выбрать файлы (или git add -A — все)
git diff --staged                   # ещё раз глянуть, что войдёт
git commit -m "Поменять текст на главной"
```

Перед коммитом убедись, что среди файлов нет `.env`, ключей и личных данных.

## 7. Как сделать push

```bash
git push
```

Изменения уйдут на GitHub в ветку `main`. **Если подключён Cloudflare Pages — через 1–2 минуты сайт обновится автоматически.** Хочешь сначала посмотреть — работай в ветке:

```bash
git switch -c new-button     # новая ветка
# ...изменения, commit...
git push -u origin new-button
```

Cloudflare соберёт preview по отдельному адресу (в demo-режиме), а сайт не изменится. Когда всё устраивает — на GitHub создай Pull Request и нажми **Merge** в `main`.

## 8. Как понять, что сайт обновился

1. GitHub → **Actions**: последний запуск CI зелёный.
2. Cloudflare → **Workers & Pages → museum-of-ordinary-things → Deployments**: верхняя строка — твой коммит (то же описание и первые символы хеша), статус **Success**.
3. Открой сайт и обнови страницу с очисткой кэша (Cmd+Shift+R / Ctrl+Shift+R).

Сервер (Supabase) от push **не** обновляется — только вручную (docs/DEPLOY.md).

## 9. Как откатить изменения

- **Быстро вернуть сайт:** Cloudflare → Deployments → прошлая успешная версия → **Rollback to this deployment**. Код при этом не меняется.
- **Отменить коммит в коде** (безопасно, история сохраняется):

```bash
git log --oneline -10        # найти хеш плохого коммита, например a1b2c3d
git revert a1b2c3d           # создаёт новый коммит, который отменяет старый
git push                     # сайт пересоберётся без этих изменений
```

- **Отменить несохранённые изменения в файле:** `git restore src/pages/HomePage.tsx`.

Не используй `git push --force` и `git reset --hard` на `main` — они стирают историю.
